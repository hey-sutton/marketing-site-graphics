# Coffee roasting graphics: generator and tests

This folder is the source for `graphics/coffee-roasting/card-1.js` to `card-4.js`. The Graphic Key is `coffee-roasting` (the CMS slug is `coffee-roasting-software`, so the Graphic Key field must be set explicitly). The key is not in `manifest.json` yet: the release owner adds `"coffee-roasting": [1, 2, 3, 4]` and bumps the version.

* **Frame:** the same as Food co-packing, Automotive, Frozen food, Pharmaceutical and Bakery. `build.py` uses `tools/automotive/frame_auto.py` on the shared Watch and Try it frame (`tools/electronics/frame.py`) and changes the key and label. It also moves the first action to 900 ms (the ghost cursor appears at `startDelay` 750 plus 150 ms), as the coffee README asks.
* **Build:** `python3 tools/coffee-roasting/build.py` rebuilds all four, or pass card numbers.
* **Cards:** `card1.py` to `card4.py` each hold one card: CSS, window HTML, data, render code and the step list. Every number on screen is computed from the data in the card (grams, cents, minutes), not typed in as text.
  1. Roast Planning & Scheduling, board: a day strip with a Day, Week and Month toggle, a stage board (Pick, Roast, Rest, Pack) with the Roaster 1 queue, an order tray (drag W-2041 onto the board, or click it), packing stations by bag size and a rush order that shows what it moves before you confirm. Background 1.
  2. Green Lots & Roast Yield, record form with a side summary: the green lot record, the roast log with the scale reading, the trace panel; on the side green on hand by origin, shrink by origin and roast level, and roasted lots. Background 2.
  3. Blends & Bean Substitution, list and detail: the blend list and a substitution panel on the left; the blend BOM with a resize field, cost per bag and versions on the right. Background 3.
  4. Packing, Labels & Shipping, stage chain: five boxes (Roasted, Packed, Labeled, Allocated, Shipped) with running totals, the pack breakdown, the label, open wholesale orders by customer and bag size, and the sales order with carrier rates and tracking. Background 4.
* **Numbers changed from the page README:** card 2's example said 60 kg of green roasted to 50.4 kg is a 14.0% loss. That is a 16.0% loss. The card keeps 14.0% and uses 51.6 kg roasted (8.4 kg lost). `test_card2.py` asserts both figures so the correction stays on record.
* **Inputs are real inputs:** typing works and Enter submits, with a sample button where there is a field (GL-4471 on card 2, RL-8820 on card 4). The roasted weight on card 2 and the resize field on card 3 come pre-filled (the scale reading and the production batch size) and can be edited. Invalid input shows an inline error and does not advance.
* **Tests:** `test_card1.py` to `test_card4.py` run the Automotive harness (`tools/automotive/auto_tests.py`) through `cr_tests.py`. `cr_tests.py` rebuilds the banned word list without "subscription" (subscription orders are a real channel for roasters, card 4) and adds claim words (certified, validated, FDA, FSMA, SQF, HACCP, audit ready), "recipe", size words, concept tags, and real roaster, importer, retailer and carrier names. Each test first asserts every sum, conversion and percentage in Python, then checks the empty start screen, timing, Watch and Try it with every caption and number, typing and Enter, Replay, the toggle, the arrows, the Studio popover by click and by touch, reduced motion, both window edges at four widths, the control row at five card widths, every step at 390 and 340 px, a text scan, the card size and the background standard. Each also walks every step with the keyboard only (focus and Enter). Card 1 also drags the order onto the board and checks that the day, week and month views count Wed 18 the same at every step.
* `shots.py N [card widths]` steps one card through Try it and saves a screenshot per step.

Run with `pip install playwright pillow` first. Set `PW_CHROME` to use a Chromium binary already on the machine. Screenshots go to `GFX_SHOTS` (default `/tmp/cr_shots`).

Preview page: `python3 tools/electronics/make_preview_page.py --card graphics/coffee-roasting/card-1.js --bg graphics/coffee-roasting/bg-1.jpg --out preview1.html`.

The backgrounds are copies of `graphics/food-co-packing/bg-1.jpg` to `bg-4.jpg` (604 by 540, progressive JPEG, about 50 KB), each used once. All names, quantities and readings are invented sample data for illustration. Several flows are screens built on Studio, so they show what Sutton can be configured to do rather than a fixed shipped screen.
