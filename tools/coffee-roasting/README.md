# Coffee roasting graphics: generator and tests

This folder is the source for `graphics/coffee-roasting/card-1.js` to `card-4.js`. The Graphic Key is `coffee-roasting`. The CMS page is `/industries/coffee-roasting-software`, so the Graphic Key field must be set to `coffee-roasting` explicitly; the loader's slug fallback would look for `coffee-roasting-software`.

* **Frame:** the same as Bakery, Food co-packing, Automotive, Frozen food and Pharmaceutical. `build.py` uses `tools/automotive/frame_auto.py` on the shared Watch and Try it frame (`tools/electronics/frame.py`) and only changes the key and label. That layer applies the November 11, 2026 UI rules: icon only Replay, control row order Studio, toggle, step counter, Replay, two lines with 40 px controls under 600 px, no plan wording in the Studio popover, and no nav or profile.
* **Build:** `python3 tools/coffee-roasting/build.py` rebuilds all four, or pass card numbers.
* **Cards:** `card1.py` to `card4.py` each hold one card: CSS, window HTML, data, render code and the step list. Every number on screen is computed from the data in the card (grams, milligrams and cents, so sums are exact).
  1. Roast Planning & Scheduling, board: a day strip with a Day, Week, Month toggle, an order tray, four stage columns (Pick, Roast, Rest, Pack), packing stations and a rush panel. Dropping SO-5120 (40 × 12 oz, 8 × 5 lb, 31.751 kg roasted) creates 3 batches of 12.000, 12.000 and 7.751 kg; Thursday reads Pick 6, Roast 6, Rest 6, Pack 4 in all three views; the 12 oz station holds 64 of 120 bags (53.3%) and the 5 lb station 14 of 30 (46.7%); pulling rush order SO-5131 into 11:00 moves exactly B-415 and B-416 by one slot. The order card can be dragged onto the board or clicked. Background 1.
  2. Background 3.
  4. Background 4.
* **Correction to the brief:** the brief's card 2 example of 60 kg green in and 50.4 kg roasted out is a 16.0% loss, not 14.0%. The card uses 60.000 kg in and 51.600 kg out, which is the stated 14.0%. `test_card2.py` asserts both.
* **Units:** 1 oz = 28.3495 g and 1 lb = 453.592 g, so a 12 oz bag is 340.194 g and a 5 lb bag is 2,267.960 g. The pack counts are chosen so the rounded kilogram lines also add up on screen.
* **Inputs are real inputs:** typing works and Enter submits, with a sample button where there is a field. Fields that hold a planned value (the 60.000 kg charge, the 51.600 kg scale reading, the 120 kg production batch) are prefilled once the step is reached and can be typed over. Invalid input shows an inline error and does not advance.
* **Tests:** `test_card1.py` to `test_card4.py` run the Automotive harness (`tools/automotive/auto_tests.py`) through `cr_tests.py`, which adds claim words, size words, concept tags and real coffee brands, importers, roasters, retailers and carriers to the banned words. Each first asserts every sum, conversion and percentage from the brief in Python, then checks the empty start screen, timing, Watch and Try it with every caption and number, typing and Enter, Replay, the toggle, the arrows, the Studio popover by click and by touch, reduced motion, both window edges at four widths, the control row at five card widths, every step at 390 and 340 px, a text scan, the card size and the background standard. Card 1 also checks the drag and drop and that stage counts match across the three views.
* **UI check:** `python3 tools/automotive/check_demo_ui.py --html previewN.html --widths 1300 390 340`, and `--cards` on the four previews (none on all four for nav and profile).
* `shots.py N [card widths]` steps one card through Try it and saves a screenshot per step.

Run with `pip install playwright pillow` first. Set `PW_CHROME` to use a Chromium binary already on the machine. Screenshots go to `GFX_SHOTS` (default `/tmp/coffee_shots`).

The backgrounds are copies of `graphics/brewery/bg-1.jpg` to `bg-4.jpg` (604 by 540, progressive JPEG, about 50 KB). All names, quantities and readings in these demos are invented sample data for illustration.
