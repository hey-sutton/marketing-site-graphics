# Wineries and cideries graphics: generator and tests

Source for `graphics/wineries/card-1.js` to `card-4.js`, page /industries/wineries, Graphic Key `wineries`. All four cards are built. The manifest, the version, the loader and the release tag are left to the release owner: the release adds `"wineries": [1, 2, 3, 4]` to `manifest.json`, bumps the version and is tagged on the merged main commit. Set the CMS item's Graphic Key to `wineries`.

**Key note:** the page brief names the folder `graphics/wineries` in its header and How to build section, but its per card lines say `graphics/wineries-cideries/card-N.js`. The per card lines were treated as a typo: everything lives under `wineries`, matching the Graphic Key.

* **Frame:** the same as Nut processing. `build.py` uses `tools/automotive/frame_auto.py` on the shared Watch and Try it frame (`tools/electronics/frame.py`, 716 by 640 window, step arrows, ripple hotspots, Studio badge and popover, Replay, aria labels, reduced motion), with the first action at 900 ms.
* **Build:** `python3 tools/wineries/build.py` rebuilds all four, or pass card numbers.
* **Card 1: Blends & Bottled Cost.** Record form with a side summary. Background 1. Open Reserve Red (read only): 75% Cabernet Sauvignon, 15% Merlot, 10% Cabernet Franc. Scale to 1,200 cases (preset case chips): 8,100 + 1,620 + 1,080 = 10,800 L. Convert: 10,800 L / 0.75 = 14,400 bottles / 12 = 1,200 cases. Cost: blend $4.19 per liter (3.15 + 0.54 + 0.50), bottle 3.1425 + 0.62 + 0.38 + 0.12 + 0.21 = $4.4725, shown $4.47; case 12 x 4.4725 = $53.67 + $1.40 carton = $55.07. Save the screwcap ($0.29) change as version 2: bottle $4.3825 shown $4.38, case $52.59 + $1.40 = $53.99, $1.08 less; version 1 still lists $55.07.
  * **Rounding:** money is held in units of 1/10,000 dollar. The case is built from the unrounded bottle cost, because 12 x $4.47 would give $53.64, not the brief's $53.67. The bottle cost is shown rounded to the cent and the unrounded figure sits beside it (BOM total row and "12 bottles at $4.4725").
* **Card 2: Dry Goods & Bottling Dates.** Board, one row per dry good, with lanes for orders arriving by Mar 14 and after it. Background 2. Open the plan (read only "Reserve Red, bottling Mar 14, 1,200 cases"): need 1,200 x 12 = 14,400 each. Check stock and arrivals: glass 9,000 on hand and 6,000 (PO-2188) arriving Mar 28, after the date, so 9,000 count; corks 12,000 + 4,000 Feb 20 = 16,000, 1,600 over; capsules 14,400, exact; labels 15,000, 600 over. Check for shortages: glass red, 5,400 short, the Mar 28 order flagged late; the others show no flag. Create PO beside glass: PO-2207 from Ridgeline Glass Co, 5,400 / 700 rounded up = 8 pallets, 5,600 bottles, arriving Mar 6. Place order: glass 14,600 against 14,400, 200 over, the row turns green and the plan clears.
* **Card 3: Lots from Cork to Case.** List and detail. Background 3. Search CK-2410-77 (read only): Alder Cork Supply, 16,000 received Oct 14, 2024. Bottling runs tab: BT-0318 Reserve Red 500 cases 6,000 corks, BT-0322 Reserve Red 400 cases 4,800, BT-0327 Estate Rose 300 cases 3,600; 14,400 used, 16,000 = 14,400 + 1,600 left. Cases and accounts tab: Harbor Wine Co 300 and club release 200 (BT-0318), Northside Distributors 400 (BT-0322), Harbor Wine Co 100 and web orders 200 (BT-0327); each run shipped equals its cases, 1,200 in all. Dates tab: cork received Oct 14, glass GL-5532 received Feb 3, runs bottled Mar 18, Mar 22 and Mar 27. Trace order beside SO-6120 (Northside Distributors, 400 cases): one run BT-0322, one cork lot CK-2410-77, one glass lot GL-5532.
* **Card 4: Allocation Across Channels.** Stage chain (Open, Picking, Packed, Shipped) with running counts. Background 4. Open Cellar Select Syrah (read only "Cellar Select Syrah, 300 cases"): three restaurant orders (50, 40, 30) on the chain. Count cases: 300 = 120 + 180. Place the distributor order (Westvale Distributing, preset 100 case chip): 300 = 220 + 80. Add the club order (fall release, preset 60 case chip): 300 = 280 + 20. Advance SO-7410: it moves to Shipped and shows Open, Picking, Packed, Shipped; shipped cases stay promised, so the counts hold at 300 = 280 + 20. The count log checks bottled = promised + free on every line.
* **Read only demos:** every input is prefilled, `readonly`, `tabindex="-1"`, gray and ignores the pointer. No typing, no typing animation, no sample buttons, no input errors. Every step is one click. Case quantities come from preset chips.
* **Tests:** `test_card1.py` to `test_card4.py` (through `wn_tests.py`, the Automotive harness with the read only checks) first assert every sum, conversion and percentage from the brief in Python, then check each on screen, plus the start screen (inputs prefilled and read only, nothing derived, no editable field), timing, Watch and Try it, Replay, the arrows, the Studio popover, reduced motion, edges at four widths, 390 and 340 px, a keyboard only walk and a mouse only walk at 604 and 358 px (Done in 5 clicks). The text scan bans dashes as punctuation, "recipe", "native", "API", certification words and real wine, cider, distributor, retailer, dry goods supplier and carrier names.
* `shots.py N [card widths]` saves a screenshot per step.

Run with `pip install playwright pillow`. Set `PW_CHROME` to a Chromium binary already on the machine.

The backgrounds are copies of `graphics/food-distributors/bg-1.jpg` to `bg-4.jpg`, one per card (604 by 540, progressive JPEG, about 50 KB). All names, quantities and readings are invented sample data for illustration.
